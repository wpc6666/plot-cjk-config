🤔 为什么会出方框

默认配置下画中文图会出方框（□□□）。原因不是"没装字体"，而是三套工具链各有各的坑：

R · pdf()
不嵌中文字体，只塞 Helvetica。中文全丢，报 conversion failure in 'mbcsToSbcs'
R · cairo_pdf()
按 family 精确匹配，不做字形回退。基座是英文字体时，含中文的元素全变 □
Python · matplotlib
字体缓存在 ~/.matplotlib/fontlist-*.json，过期就不认新字体，悄悄回退 DejaVu
Stata · graph export
只设 fontface 一项，另外 4 项仍是 Helvetica。刻度、注释回退 → □

🔬 实测依据

同一个中文标题在 PDF 里的墨迹像素数（越接近 0 越说明字没画出来）。pdf.fonttype=42 下：

字体墨迹像素轮廓格式结论
PingFang SC0CFF文字层正确但视觉全空，最阴的一类 bug
Songti SC1195TrueType正常
Heiti SC1344TrueType正常
Arial Unicode MS1378TrueType正常
Noto Sans SC748TrueType正常，但只有 weight 100，偏细

关键差异：ragg 会回退，cairo 不会

ragg（PNG）有自动字形回退，基座是英文字体也能渲染中文 → PNG 天然安全。
cairo（PDF）精确匹配字体，缺字就画框 → PDF 是重灾区。
所以本项目保持 pdf.fonttype 默认值 3。

🕳️ 踩过的坑（不报错但静默失效）

1 · Source Han Sans SC 假命中

systemfonts::match_fonts("Source Han Sans SC") 返回 /System/Library/Fonts/Helvetica.ttc。不存在的字体名被"宽容"匹配到英文字体，图出来全是 □，零报错。

2 · register_font() 对 cairo 无效

用 systemfonts::register_font(name="sans", ...) 看似注册成功，但 cairo_pdf() 实际还是 Helvetica。cairo 设备不读 systemfonts 注册表，必须显式传 family=。

3 · PingFang 放在奇怪的位置

PingFang.ttc 不在 /System/Library/Fonts，而在 /System/Library/AssetsV2/...。R 走 fontconfig 能扫到，matplotlib 扫不到，必须用 fm.fontManager.addfont() 手动注册。

4 · .Renviron 盖掉 shell 的 export

测试新 profile 必须用 Rscript --no-environ，否则加载的还是旧的那个。

5 · Stata graph set pdf 是空操作

只有 window/ps/eps/svg 四个有效目标，PDF 导出实际走 ps。

❓ 常见问题

装完后 RStudio 里还是方框？

重启 RStudio。.Rprofile 只在启动时读一次。

Jupyter 里字体不对？

确认 import mpl_setup 在 import matplotlib.pyplot 之前。mpl_setup 会在导入时强制刷新 rcParams。

装了新字体，matplotlib 不认？

rm -rf ~/.matplotlib/fontlist-*.json，或直接 import mpl_setup（它会主动扫描并注册）。

为什么不用思源黑体？

装了也能用，但本项目的默认选择是系统自带、零安装。思源黑体可变字体只有 weight 250，Noto Sans SC 只有 100，都会让标题异常纤细。Arial Unicode MS 覆盖 100–400，且是 macOS 上唯一同时覆盖中文与数学符号（ρ √ → ∞ ≤ ≥）的系统字体——PingFang 字形更美但缺数学符号，画统计图会出方框。

Linux / Windows 能用吗？

不能。脚本开头有平台检查，只支持 macOS。
